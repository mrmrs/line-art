# Code review — 12 November 2026

Reviewed the pending application changes, including the vendored renderer integration, continuous occlusion, geometry and fill caches, packed composition and recursion, worker scheduling, SVG export, persistence integration, and interface controls. The feature work was split among interface, navigation, and fill/randomization agents, with an independent cross-review of composition, export, and randomization.

## Findings resolved

- Preset replacement cleared the scene before loading, creating a redundant undo state and risking loss of the current scene if replacement validation failed. It now validates and replaces in one store action.
- Cube grids had no fill host. They now tessellate within a triangle budget and support hatch, surface hatch, dots and contours. Surface patterns can select world-axis face families while retaining full-host occlusion.
- Randomizing text layout must regenerate its cached contours. Font loading and contour generation complete before one guarded store update; stale asynchronous work cannot replace subsequent edits.
- Composition randomization generates from the new recipe before committing recipe and instances together. Cancellation preserves the prior state; keeping a form preserves its resolved geometry.
- Dependency audit found development-tool vulnerabilities. Compatible updates plus a patched minimatch override resolve the reported advisories without downgrading ESLint. The override should be removed when upstream lint dependencies adopt the patched major version.
- The browser test port conflicted with another local project. `PLAYWRIGHT_PORT` now allows an isolated test server without stopping that project.
- Vendor documentation identified 0.8.0 while the lockfile installed 0.8.1; corrected.

| Before | After | Why |
| --- | --- | --- |
| Brand text and tagline | Supplied striped SVG mark | Compact identity |
| Preset cards with persistent descriptions | Icon grid or icon/title list, hover/focus descriptions | More space for artwork |
| Shape controls required manual exploration | Bounded, undoable randomization | Rapid variation |
| Cube grids lacked fill controls | Layered patterns and face-family controls | Side shading and multi-pen output |

- Orthographic wheel gestures repeatedly replaced exact artwork with wireframes; they now reuse the SVG until the gesture settles. Perspective dolly zoom incorrectly applied a flat CSS scale; it now uses projected previews. The fixed viewport background also prevents a shrinking-paper illusion on zoom-out. Both new regressions failed before the fix and pass afterward.

Navigation-specific reproduction, fixes, measurements, and tradeoffs are recorded in [navigation-performance.md](navigation-performance.md).

## Validation and limits

Engine tests cover geometry, clipping, cache consistency, physical output, composition packing, ancestry, bounded randomization, side targeting, and per-pen grid fills. Browser tests cover scene reload, export/cancellation, composition persistence and pins, preset replacement undo, deletion affordances, randomization, camera interactions and worker delivery. Lint and the production build are required before commit. Dependency audit reports zero known vulnerabilities after the updates.

Review and browser validation use local Chrome. No physical pen plot or cross-browser certification was performed. Dense fill construction remains subject to explicit geometry/work limits. Face selectors classify world-space normals, so rotated grids are classified by their world-facing sides. Temporary navigation wireframes intentionally omit hidden-line removal; exact rendering returns after interaction.

Final verification: **65 engine tests and 21 Chrome browser tests passed**, along with `npm run lint`, `npm run build`, `git diff --check`, and a zero-vulnerability `npm audit`. The final dense navigation fixture displayed 60 distinct frames during a 2.03-second drag with one outstanding request and one camera commit.

## Follow-up: counters and paper guides

Added anonymous export-delivery and accepted OBJ/STL/SVG import counters using the existing Cloudflare endpoint. Initial reads and post-increment refreshes parse plain text; HTTP failures, timeouts and offline errors are ignored without POST retries. The browser fixture mocks every counter request so automated tests do not change production totals. A read-only live GET verified endpoint format and CORS.

Paper framing now uses the same dimensions and camera projection as export. Click/focus/wheel selection identifies the active export camera without recording an undo entry. Grid guides use physical millimeter coordinates and remain outside rendering/export data. The visible frame is the paper edge; configured export margins still apply separately. Export metadata identifies Skullcat/mrmrs without changing path geometry. The header mark is optically centered and file actions read Open/Save.

Final follow-up verification: **70 unit tests, 27 Chrome browser tests, lint, production build and whitespace checks passed**. Browser tests compare preview paths directly with export projection for square, A4, landscape and Letter papers in orthographic and perspective modes; they also verify grid isolation, camera selection, counter success/failure behavior and offline artwork operations.

## Follow-up: orientation and custom paper

Paper controls now switch portrait/landscape and accept custom dimensions in inches, millimeters or centimeters. Physical dimensions remain canonical in millimeters; display-unit changes do not resize the sheet. Preview, grid and SVG export share the resolved dimensions. Custom paper is bounded to 40–2,000 mm per side and a maximum render dimension of 2,400 pixels while preserving aspect ratio. Packed compositions retain their forms; margins and quiet regions remain valid after resizing.

Verification: **72 unit tests and 31 Chrome browser tests passed**, plus lint/build/whitespace checks. New browser cases verify portrait/landscape export dimensions, 8×10 inch conversions, unit switching, invalid/cancelled drafts, and composition resize with existing generated forms. The custom editor was visually inspected at 1280 pixels.
